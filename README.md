# Trade — core-only движок (MOEX)

**100% капитала в core** — без satellite. Раз в месяц:

1. **Скан всей биржи** (акции TQBR) → топ-20 по momentum + ликвидность  
2. **Обновление `.env`** (`CORE_UNIVERSE`)  
3. **Пополнение** + ребаланс: из 20 держим **топ-5** с весами 1/σ  

## Команды

```bash
pip install -r requirements.txt
cp .env.example .env

# Разовый / ручной месячный скан
python3 -m bot.scan

# Paper-бот (скан автоматически в новом месяце)
python3 -m bot

# Бэктест (walk-forward: скан на каждый месяц по истории)
python3 -m bot.backtest
```

Отчёты скана: `data/scans/scan_YYYY-MM.json` и `.txt`.

## Скоринг и прогноз (по умолчанию — строгий)

**Входные данные:**

| Слой | Источник |
|------|----------|
| Цена/объём | MOEX ISS |
| Макро | IMOEX, USD/RUB (MOEX), ключевая ставка ЦБ |
| Фундаментал | МСФО ЦКИ MOEX (если есть подписка), иначе прокси: оборот 3м + капитализация |
| Новости | MOEX sitenews (упоминания тикера + тон заголовка) |

**Строгий режим (`.env`):** `SCAN_MIN_FORECAST_PCT=1`, `SCAN_STRICT_ONLY=true`

Фильтры: mom6m&gt;0, не ниже SMA50 более чем на 3%, обгон IMOEX, сигнал роста (оборот или momentum), прогноз ≥ +1%/мес.

В слабый рынок в universe может попасть **меньше 20** имён — это нормально.

Модель переобучается при каждом скане. Это **оценка по истории**, не гарантия будущего роста. Прогноз может быть **отрицательным** — это сигнал слабости, не только для отбора в universe.

## Продажа по прогнозу падения (с учётом комиссии)

Помимо ежемесячного ребаланса (выпадение из топ-5), бот **каждый цикл** (`POLL_INTERVAL_SEC`) пересчитывает прогноз по открытым позициям:

| Параметр | По умолчанию | Смысл |
|----------|--------------|--------|
| `EXIT_ON_NEGATIVE_FORECAST` | `true` | Включить досрочные выходы |
| `SCAN_SELL_FORECAST_PCT` | `-1.0` | Продать, если прогноз &lt; −1%/мес |
| `EXIT_FEE_BUFFER` | `1.2` | Запас к круговой комиссии (покупка+продажа) |
| `COMMISSION_PCT` | `0.1` | Комиссия брокера на сделку, % |

**Логика:** полная продажа с тегом `EXIT`, только если ожидаемый убыток за месяц **больше** `2 × COMMISSION_PCT × стоимость позиции × EXIT_FEE_BUFFER`. Иначе держим — иначе комиссия съест выгоду от «мелкого» выхода.

В бэктесте те же правила проверяются **каждый торговый день**.

### Настройка строгости

| Параметр | Эффект |
|----------|--------|
| `SCAN_MIN_FORECAST_PCT=2` | Ещё выше порог прогноза |
| `SCAN_MIN_AVG_TURNOVER_RUB=50000000` | Только голубые фишки |
| `SCAN_REQUIRE_MACRO_RISK=true` | Отсекать при плохом макро-фоне |
| `SCAN_SMA_TOLERANCE_PCT=0` | Строго выше SMA50 |

## Дивиденды

**Источник суммы:**

1. **MOEX ISS** — `securities/{TICKER}/dividends.json`: объявленные выплаты с датой отсечки и `value` на акцию.
2. **Прокси** — если отсечки в горизонте нет: оценка по истории MOEX за `DIVIDEND_HISTORY_MONTHS` (36 мес), с учётом **реального цикла** выплат (раз в год / раз в 3 года — не «/12 каждый месяц»).

**Понижающие коэффициенты:**

| Ситуация | Коэф. | Эффект |
|----------|-------|--------|
| Нет выплат в истории MOEX | `DIVIDEND_NO_INFO_DISCOUNT` (0.85) | total-прогноз × 0.85 |
| Редкие выплаты (1 раз / цикл ≥ 2 лет) | `DIVIDEND_SPARSE_DISCOUNT` (0.90) | только div-часть × 0.90 |

```env
INCLUDE_DIVIDENDS=true
DIVIDEND_TAX_PCT=13
DIVIDEND_USE_PROXY=true
DIVIDEND_PROXY_MONTHS=12
DIVIDEND_HISTORY_MONTHS=36
DIVIDEND_DEFAULT_CYCLE_DAYS=365
DIVIDEND_NO_INFO_DISCOUNT=0.85
DIVIDEND_SPARSE_DISCOUNT=0.90
```

| **Paper / live** | Только **реальные** выплаты MOEX на дату отсечки |
| **Скан / EXIT** | total с коэффициентами неопределённости |
| **Бэктest** | Фактические дивиденды MOEX по календарю |

В отчёте скана: выплат за 36 мес, цикл, `×0.85` если нет данных.

Не является инвестиционной рекомендацией.
